# Validation

## The decomposition that makes this tractable

No 3D boolean engine. Not needed, because every unit is a prism:

> Two units intersect **iff** footprints intersect **AND** z-intervals overlap.

```python
tree = shapely.STRtree(footprints)          # never O(n^2)
for c in tree.query(unit.footprint):
    if not z_overlap(unit, c, tol_v): continue
    if unit.footprint.buffer(-tol_h).intersects(c.footprint.buffer(-tol_h)):
        emit Error
```

The **inward buffer by the tolerance** is what separates a shared wall (adjacent flats
touch by definition — normal) from real penetration (a finding).

## Tolerance from provenance — the distinctive piece

```
tol_h = k * sqrt(acc_h(a)^2 + acc_h(b)^2)     # k = 1.0 for 1 sigma, 1.96 for 95%
tol_v = k * sqrt(acc_v(a)^2 + acc_v(b)^2)
```

Accuracies come from P2's source registry, per unit, via `source_ids`.

**Never hardcode a tolerance constant.** If a footprint was captured at 30 cm accuracy, a
5 cm overlap with its neighbour is *measurement noise*, not an encroachment. Reporting it
wastes reviewer attention and trains people to click through warnings — which silently
destroys the human-in-the-loop guarantee the entire system rests on.

Pitch line: *"our validation tolerance is a function of the source data's stated accuracy,
so we never report a conflict smaller than our ability to measure it."*

This creates a hard dependency on P2: `horizontal_accuracy_m` and `vertical_accuracy_m`
must be **mandatory** columns, not optional.

## Rules

| Rule | Computation | Severity |
|---|---|---|
| `GEOM_INVALID` | `shapely.is_valid` | Error |
| `Z_IMPOSSIBLE` | `lower >= upper` | Error |
| `OVERLAP_SIBLING` | STRtree → z-interval → buffered footprint intersection | Error |
| `GEOM_DUPLICATE` | normalised WKB hash + matching z-range | Error |
| `ESCAPES_PARENT` | `child.difference(parent).area > tol` — **type-conditional** | Error / expected |
| `FLOOR_SEQUENCE` | sorted by `floor_index`; `floor[i].upper ≈ floor[i+1].lower` | Error |
| `UTILITY_CROSSES_BUILDING` | easement ∩ building/floor/apartment volume | Error |
| `GAP_SIBLING` | `parent.difference(union(children)).area > tol` | **Warning** |
| `FLOOR_HEIGHT_IMPLAUSIBLE` | outside 2.4–5.0 m | Warning |
| `CONFIDENCE_LOW` | below project threshold | Warning |
| `CRS_MISMATCH` / `DATUM_MISMATCH` | source vs project reference system | Error |
| `PROVENANCE_MISSING` | null `source_ids`, accuracy or confidence | Info |

**Error** blocks approval · **Warning** requires reviewer acknowledgement · **Info** is
advisory. Thresholds live in the project rule set (FR-01), not in code.

## Two rules most teams get wrong

**1. The gap check is a Warning, not an Error.** Corridors, lift shafts and stairwells
legitimately leave gaps when only apartments are modelled. Erroring here flags every real
building. Floors with `subdivided=false` must not be gap-checked at all.

**2. Containment is type-conditional.** Underground and elevated units are *easements*,
not ownership volumes. Crossing a parcel boundary is normal and expected for them — a
tunnel confined to a single parcel would be the anomaly. Crossing a *building volume* is
still an Error (a water main through someone's flat). **Ownership volumes must not overlap;
easement corridors are supposed to.**

## What we cannot detect

A **uniform vertical offset applied to everything**. Every relative relationship stays
consistent, so all our checks pass cleanly on a building sitting 40 m underground. Only
P2's per-source `vertical_datum` recording can prevent this; we can catch sources that
*disagree* with each other, not a consistent error.

## The fixture

`cadastre/contracts/fixtures/demo-parcel.json`, generated by
`cadastre/tools/make_fixture.py` (edit the generator, never the JSON).

16 units, 24 relationships, 7 sources: one parcel plus a neighbour, an 8-storey building
(basement + 7), three flats on the first floor, a water main, an elevated walkway.
Geometry is deliberately **axis-aligned** so overlap areas are exact arithmetic and
expected findings can be asserted to the square metre.

Planted defects — one per severity path, so the review UI exercises more than the happy
path:

| Rule | Severity | What |
|---|---|---|
| `OVERLAP_SIBLING` | error | APT-103 penetrates APT-102 by 7.2 m² |
| `FLOOR_SEQUENCE` | error | 0.4 m gap between FLR-004 and FLR-005 |
| `UTILITY_CROSSES_BUILDING` | error | water main at 910.4–911.9 runs through the basement |
| `FLOOR_HEIGHT_IMPLAUSIBLE` | warning | ground floor at 5.5 m |
| `PROVENANCE_MISSING` | info | SRC-007 has null accuracy |

### `must_not_fire` — the negative tests, and the more valuable half

- **`ESCAPES_PARENT` on UGF-001.** The water main spans both parcels and extends beyond
  them. It must **not** be flagged. A validator that flags it has implemented containment
  unconditionally and is wrong.
- **`GAP_SIBLING` on FLR-001.** The three flats tile it exactly.

Negative tests are what stop a validation engine degenerating into "flag everything",
which is the failure mode that actually kills these systems — not missed errors, but so
much noise that reviewers stop reading. **Encoding the silence you expect is as much a
specification as encoding the alarms.**
